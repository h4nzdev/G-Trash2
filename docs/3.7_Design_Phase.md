# 3.7 Design Phase

The design phase of the G-TRASH project focused on transforming the gathered system requirements into a concrete, visual interface and a stable data structure. The goal was to ensure the platform is highly functional, user-friendly, and perfectly tailored to the specific roles of each user. This phase was divided into two parallel parts: **Interface Design** (focusing on layout and user interaction) and **Database Design** (focusing on data structure and relationships), ensuring that the visual screens perfectly matched the underlying data flow.

To guide the development of the mobile and web platforms, the design strictly followed three key principles:

- **Simplicity:** Crucial for field use, ensuring garbage collectors can operate the app easily while the truck is moving.
- **Clarity:** Essential for residents, allowing them to easily understand local pollution levels and pinpoint the exact location of the garbage truck.
- **Scalability:** Necessary for administrators, utilizing highly organized dashboards that can handle large amounts of city-wide data without becoming cluttered.

The system's front-end architecture was built using **React Native** for the mobile applications and **React** paired with **Tailwind CSS** for the web dashboards. The visual identity was anchored by a clean, environmental color system: a Primary green (`#006A3B`), a neutral Background (`#FBF9F8`), and a highly readable Text color (`#1B1C1C`).

## 3.7.3 Database Design

### A. Database Technology

The system uses **MongoDB** (NoSQL) as its primary database, accessed through **Mongoose ODM** in the Node.js backend. MongoDB was selected for its flexible document schema, which accommodates the varied data shapes across IoT sensor readings, GPS coordinates, and user-generated reports.

### B. Collection Schema Overview

The database consists of **10 primary collections** organized into four functional domains:

#### Domain 1: Vehicle Tracking & Fleet

| Collection       | Key Fields                                                      | Purpose |
|------------------|-----------------------------------------------------------------|---------|
| `trucks`         | `truckId`, `lat`, `lng`, `heading`, `speed`, `status`, `updatedAt` | Real-time GPS position of each garbage truck |
| `fleets`         | `truckId`, `driverName`, `route`, `createdAt`                    | Fleet registry mapping trucks to assigned drivers |
| `collectionlogs` | `truckId`, `date`, `stopName`, `wasteType`, `weight`, `bins`, `routeId` | Per-stop collection records for historical analysis |

#### Domain 2: Route & Schedule Management

| Collection    | Key Fields                                                              | Purpose |
|---------------|-------------------------------------------------------------------------|---------|
| `routes`      | `name`, `truckId`, `driverName`, `barangay`, `waypoints[]`, `routeCoords[]`, `totalStops` | Defined collection routes with ordered waypoints |
| `schedules`   | `date`, `truckId`, `driverName`, `routeId`, `routeName`, `startTime`, `notes` | Daily route assignments linking trucks to routes on specific dates |

#### Domain 3: Environmental Monitoring & Reporting

| Collection      | Key Fields                                                               | Purpose |
|-----------------|--------------------------------------------------------------------------|---------|
| `reports`       | `title`, `category`, `description`, `location`, `barangay`, `lat`, `lng`, `priority`, `status` | Resident-submitted waste reports with auto-priority assignment |
| `garbageareas`  | `name`, `lat`, `lng`, `status`, `ammonia`, `methane`, `bins`, `intensity`, `barangay` | Mapped garbage hotspots for heatmap visualization |
| `sensorreadings`| `sensorId`, `deviceType`, `ammonia`, `methane`, `temperature`, `humidity`, `binLevel`, `airQuality` | IoT sensor data from ESP32/Arduino devices |
| `iotalerts`     | `sensorId`, `severity`, `message`, `gasType`, `value`, `threshold`, `acknowledged` | Automated alerts triggered when sensor thresholds are exceeded |

#### Domain 4: User & Access Management

| Collection   | Key Fields                                                    | Purpose |
|--------------|---------------------------------------------------------------|---------|
| `officials`  | `name`, `email`, `passwordHash`, `barangay`, `role`           | Official and superadmin accounts with barangay-scoped access |

### C. Entity-Relationship Summary

```
Officials (1) ──── manages ────> (N) Routes
Officials (1) ──── manages ────> (N) Fleets
Officials (1) ──── reviews ────> (N) Reports

Fleets    (1) ──── tracks  ────> (1) Trucks (real-time GPS)
Fleets    (1) ──── assigned ───> (N) Schedules
Routes    (1) ──── scheduled ──> (N) Schedules
Routes    (1) ──── produces ───> (N) CollectionLogs

GarbageAreas (N) <── visualized ── Heatmap Analytics
SensorReadings (N) ── triggers ──> (N) IoTAlerts

Residents (via App) ── submits ──> (N) Reports
Residents (via App) ── views   ──> Trucks (real-time location)
```

### D. Report Priority Auto-Assignment Matrix

| Report Category    | Auto-Assigned Priority |
|--------------------|----------------------|
| Hazardous Waste    | Critical             |
| Illegal Dumping    | High                 |
| Overflowing Bin    | High                 |
| Uncollected Waste  | Medium               |
| Other              | Low                  |

### E. Real-Time Communication (WebSocket Events)

| Event Name              | Direction           | Description |
|-------------------------|---------------------|-------------|
| `truck:location:update` | Server → All clients | Broadcasts GPS update when a truck sends its position |
| `truck:off-route`       | Server → Admin Panel | Alert when a truck deviates from its assigned route |
| `report:new`            | Server → Officials   | Notifies when a resident submits a new report |
| `report:updated`        | Server → All clients | Broadcasts when a report status changes |
| `fleet:new`             | Server → All clients | New truck registered in the fleet |
| `fleet:updated`         | Server → All clients | Fleet record updated (driver reassignment, etc.) |
| `fleet:deleted`         | Server → All clients | Truck removed from fleet |
| `route:new`             | Server → All clients | New route created |
| `route:updated`         | Server → All clients | Route modified |
| `route:assigned`        | Server → Truck app   | Notifies a specific truck that a new route has been assigned |
